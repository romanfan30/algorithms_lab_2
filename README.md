## Теоретическая часть (кратко)

### Бинарное дерево поиска (BST)
Для каждого узла: все ключи левого поддерева меньше его ключа, все ключи правого — больше.
Высота в худшем случае (монотонная вставка) — `O(n)`, в среднем на случайных данных — `O(log n)`.

### АВЛ-дерево
BST, в котором для каждого узла выполняется условие баланса:

```
balance = h(left) - h(right),   |balance| ≤ 1
```

**Повороты при вставке:**

| Ситуация | Действие |
|---|---|
| `balance > 1`, у левого ребёнка `balance ≥ 0` | правый поворот |
| `balance > 1`, у левого ребёнка `balance < 0` | левый поворот у левого ребёнка, затем правый (**большой левый**) |
| `balance < -1`, у правого ребёнка `balance ≤ 0` | левый поворот |
| `balance < -1`, у правого ребёнка `balance > 0` | правый поворот у правого ребёнка, затем левый (**большой правый**) |

Вставка — как в BST, затем подъём вверх: баланс `0` — остановиться, `±1` — идти выше,
`±2` — выполнить нужный поворот.

Удаление — как в BST (лист удаляется, узел с двумя детьми заменяется ближайшим по значению),
затем подъём вверх: баланс `0` — идём выше, `±1` — остановиться, `±2` — поворот
(после поворота: баланс `0` — идём выше, иначе остановиться).

**Оценка высоты.** Через числа Фибоначчи: `n ≥ F_{h+3} - 1`, откуда

```
h ≤ log_φ(n + 1) - 3 ≈ 1.44·log₂(n + 2) - 0.328,   φ = (1 + √5)/2 ≈ 1.618
```

### Красно-чёрное дерево (RB)
Самобалансирующееся BST со свойствами:

1. Каждый узел имеет цвет — красный или чёрный.
2. Корень — чёрный.
3. Все листья (в т.ч. пустые) — чёрные.
4. У красного узла оба потомка — чёрные (нет двух красных подряд).
5. Все простые пути от узла до листьев содержат одинаковое число чёрных узлов (чёрная высота `bh`).

**Вставка.** Новый узел всегда красный, ставится как в BST, затем балансировка:
*случай 0* — вставка корня (красим в чёрный); *случай 1* — красный дядя (перекраска родителя
и дяди в чёрный, дедушки — в красный, подъём выше); *случаи 2–3* — чёрный дядя
(поворот у родителя при «внутреннем» положении узла, затем поворот у дедушки с перекраской).

**Удаление.** Сначала стандартное удаление из BST, затем разбор случаев:
*0* — оба ребёнка-псевдоузла; *1* — левое поддерево непустое, правый псевдоузел;
*2* — симметрично; *3* — оба ребёнка (замена ближайшим по значению). Далее — восстановление
свойств через перекраски и повороты.

**Оценка высоты.** Красные узлы не идут подряд ⇒ `bh ≥ h/2`, и `n ≥ 2^bh - 1`, откуда

```
h ≤ 2·log₂(n + 1)
```

## Экспериментальная часть

`diagrams.py` при `n = 30 000` строит пять графиков:

1. **BST**, случайная перестановка `0..n-1` (`random.sample`).
2. **AVL**, та же случайная последовательность + теоретические границы `log₂(n+1)` и `1.44·log₂(n+1)`.
3. **AVL**, монотонно возрастающая последовательность + те же границы.
4. **RB**, случайная последовательность + границы `log₂(n+1)` и `2·log₂(n+1)`.
5. **RB**, монотонно возрастающая последовательность + те же границы.

Идея сравнения: случайные данные — «типичный» случай для BST, монотонная вставка — худший,
на котором сбалансированные деревья должны показать свою силу.

### Запуск

```bash
pip install -r requirements.txt
python diagrams.py
```

Полный прогон занимает **≈4.7 минуты** (основное время — квадратичный пересчёт высоты
для BST и RB на каждом шаге) и по очереди показывает 5 окон с графиками.

### Результаты (замер при n = 30 000, `log₂(n+1) = 14.87`)

| Структура | Данные | Высота `h` | Верхняя граница из теории |
|---|---|---|---|
| BST | случайные | 34 | нет (в худшем случае `n`) |
| AVL | случайные | 18 | `1.44·log₂(n+1) = 21.42` |
| AVL | возрастающие | 15 | 21.42 |
| RB | случайные | 18 | `2·log₂(n+1) = 29.75` |
| RB | возрастающие | 27 | 29.75 |

*(числа конкретного прогона: `random.sample` без фиксации seed, поэтому от запуска к запуску
они немного меняются, но остаются в тех же пределах)*

**Выводы:**
- BST на случайных данных держит высоту около `2.3·log₂n`, но теоретической гарантии не имеет
  и на монотонной последовательности вырождается в список (`h = n`).
- AVL строго укладывается в `1.44·log₂(n+1)` на обоих наборах данных; на монотонной
  вставке высота даже ниже, чем на случайной (`15` против `18`) — вставка в конец даёт
  почти идеально заполненное дерево.
- RB укладывается в `2·log₂(n+1)`, но его высота систематически больше, чем у AVL
  (на монотонных данных `27` против `15`): баланс AVL жёстче, зато RB дешевле перебалансирует
  при вставке/удалении.
- Нижняя граница `log₂(n+1)` нигде не нарушена — ни одно дерево не стало «лучше возможного».
